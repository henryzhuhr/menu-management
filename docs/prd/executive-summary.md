# 统一菜单中心项目简述

## 一句话概述

统一菜单中心是面向多应用、多租户、多环境、多地域、多客户端的平台级菜单配置与分发系统。它集中管理菜单、权限标识、订阅功能点、版本发布和运行时过滤，为前端提供一致、可控、可审计的导航菜单能力。

参考：[PRD 总览](./overview.md)、[D001 产品边界](./decisions/001-product-scope.md#d001-product-boundary)、[D004 系统范围](./decisions/001-product-scope.md#d004-app-scope)

## 为什么要做

当前大型平台如果由各业务系统分别维护菜单，容易出现菜单重复配置、权限口径不一致、租户差异难治理、发布不可控、问题难排查等问题。统一菜单中心的目标是把菜单从“各系统内置配置”升级为“平台统一治理能力”，让菜单配置、发布、运行时分发和审计诊断形成闭环。

参考：[D059 验收重点](./decisions/001-product-scope.md#d059-acceptance-priority)

## 建设目标

- 统一配置：集中管理平台菜单模板、租户自定义、多客户端展示和多语言文案。
- 精准分发：根据应用、环境、地域、客户端、租户、用户、订阅、权限和策略条件返回最终可见菜单。
- 安全可控：缺权限、缺订阅、依赖异常或条件不满足时默认隐藏，防止越权展示。
- 治理闭环：支持版本、灰度、审批、发布、回滚、审计、导入导出和跨环境迁移。
- 可解释：管理员可以预览和诊断某个用户在特定上下文下为什么看到或看不到某个菜单。

参考：[运行时菜单](./modules/runtime-menu.md)、[发布治理](./modules/release-governance.md)、[管理诊断](./modules/admin-operations.md)

## 核心能力

- 运行时菜单查询：后端根据上下文和规则过滤菜单，返回前端可直接展示的导航树和元数据。
- 菜单配置：支持目录、页面、外链、逻辑菜单、多客户端展示、多语言、功能点和权限标识绑定。
- 租户自定义：租户继承平台菜单模板，可新增、隐藏和排序菜单。
- 用户个性化：用户可在安全边界内排序或隐藏个人菜单。
- 外部集成：对接身份、权限、订阅系统，不重复实现这些主系统能力。
- 分析与诊断：支持菜单曝光、点击、趋势分析、可见性解释和完整诊断链路。

参考：[菜单配置](./modules/menu-configuration.md)、[租户自定义](./modules/tenant-customization.md)、[外部集成](./modules/integrations.md)、[使用分析](./modules/analytics.md)

## 明确边界

菜单中心不实现身份认证、用户授权、订阅购买、合同、计费和订单系统。外部订阅系统是租户订阅主数据源，菜单中心负责定义功能点并维护菜单绑定；外部权限系统负责用户授权，菜单中心负责绑定权限标识并消费权限结果。

参考：[D055 订阅主源](./decisions/006-integrations.md#d055-subscription-source-of-truth)、[D056 功能点主源](./decisions/006-integrations.md#d056-feature-source-of-truth)、[D058 范围排除](./decisions/001-product-scope.md#d058-out-of-scope)

## 预期价值

- 对业务：统一导航体验，减少各应用重复建设菜单能力。
- 对平台：形成菜单配置、权限订阅过滤、发布回滚和审计诊断的统一治理能力。
- 对租户：支持租户差异化菜单，同时不破坏平台统一规则。
- 对运维和运营：通过诊断和分析快速定位菜单不可见、误展示、低使用率等问题。
