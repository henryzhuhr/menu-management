# 产品范围决策

<a id="d001-product-boundary"></a>
## D001 产品边界

- 提问：这个“菜单管理系统”的需求边界先按哪一种来定义？
- 提问解释：该问题用于确认系统是只做运行时展示、同时覆盖菜单管理，还是建设为面向多个业务系统的统一菜单平台。
- 用户决策：统一菜单中心。
- 需求影响：系统定位为平台级能力，需要覆盖菜单配置、运行时分发、租户差异、版本发布、诊断分析和治理闭环。

<a id="d002-user-roles"></a>
## D002 用户角色

- 提问：首版需求里需要覆盖哪些使用角色？
- 提问解释：该问题用于确认 PRD 是否只描述普通用户菜单展示，还是需要覆盖平台和租户管理视角。
- 用户决策：平台管理员、租户管理员、普通用户。
- 需求影响：PRD 必须覆盖平台配置、租户自定义和普通用户消费三个角色链路。

<a id="d004-app-scope"></a>
## D004 系统范围

- 提问：统一菜单中心要服务的业务系统范围是什么？
- 提问解释：该问题用于确认系统服务单应用还是多应用，以及是否需要租户隔离。
- 用户决策：多应用多租户。
- 需求影响：菜单、版本、发布、权限、订阅和诊断都需要带应用和租户维度。

<a id="d058-out-of-scope"></a>
## D058 范围排除

- 提问：哪些能力明确不属于菜单中心本身？
- 提问解释：该问题用于切清菜单中心与身份、权限、订阅、计费等外部主系统之间的边界。
- 用户决策：外部主系统不实现。
- 需求影响：菜单中心不实现身份认证、用户授权、订阅购买和计费，只消费外部系统结果。

<a id="d059-acceptance-priority"></a>
## D059 验收重点

- 提问：需求验收最核心的成功标准是什么？
- 提问解释：该问题用于确认验收时优先看正确性、性能，还是平台治理闭环。
- 用户决策：治理闭环。
- 需求影响：PRD 验收重点放在版本、审批、灰度、回滚、审计、迁移和诊断等完整管理闭环。

<a id="d060-prd-shape"></a>
## D060 PRD 形态

- 提问：后续落 PRD 时，文档应该按什么结构组织？
- 提问解释：该问题用于确认 PRD 是单文件维护，还是按模块或角色拆分。
- 用户决策：按模块拆分。
- 需求影响：PRD 采用入口索引、模块文档和决策记录的结构，模块文档引用决策编号。
