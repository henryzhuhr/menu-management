# 发布治理决策

<a id="d006-publish-flow"></a>
## D006 发布流程

- 提问：菜单配置变更是否需要发布流程？
- 提问解释：该问题用于确认配置保存后是否立即影响用户，还是需要版本和灰度治理。
- 用户决策：版本灰度。
- 需求影响：菜单配置需要支持版本、发布、回滚和按范围灰度。

<a id="d009-rollout-target"></a>
## D009 灰度对象

- 提问：版本灰度发布主要按什么对象控制？
- 提问解释：该问题用于确认灰度维度是租户、用户群，还是还要包括环境和地域。
- 用户决策：租户 + 环境 + 地域。
- 需求影响：灰度发布需要支持租户、环境和地域维度。

<a id="d014-approval-flow"></a>
## D014 发布审批

- 提问：菜单版本发布是否需要审批？
- 提问解释：该问题用于确认是否所有发布都轻量化，还是关键变更需要审批控制。
- 用户决策：关键变更审批。
- 需求影响：普通变更可轻量处理，安全、删除、权限、套餐、全量发布等高风险变更需要审批。

<a id="d021-audit-history"></a>
## D021 审计历史

- 提问：管理侧变更需要什么审计和历史能力？
- 提问解释：该问题用于确认是否只记录基础日志，还是支持完整审计和回滚。
- 用户决策：完整审计 + 回滚。
- 需求影响：系统需要记录变更人、时间、内容、审批、发布和回滚，版本可追溯。

<a id="d027-runtime-freshness"></a>
## D027 生效时效

- 提问：菜单配置、订阅或权限变化后，运行时菜单何时生效？
- 提问解释：该问题用于确认运行时菜单变更是实时、分钟级，还是重新登录后生效。
- 用户决策：实时生效。
- 需求影响：需要把安全相关变更作为实时生效目标，并在 TDD 中设计对应机制。

<a id="d028-realtime-scope"></a>
## D028 实时范围

- 提问：哪些变化必须实时影响运行时菜单？
- 提问解释：该问题用于缩小实时生效范围，避免所有展示类变更都要求强实时。
- 用户决策：安全相关实时。
- 需求影响：权限、订阅、启停、发布回滚实时生效；名称、排序、图标等展示变更允许短延迟。

<a id="d043-critical-changes"></a>
## D043 关键变更范围

- 提问：哪些变更需要进入关键变更审批？
- 提问解释：该问题用于明确哪些操作属于高风险操作。
- 用户决策：安全 + 发布类。
- 需求影响：权限、订阅、删除/停用、全量发布、回滚、跨地域变更、强制菜单变更需要审批。

<a id="d044-approval-policy"></a>
## D044 审批规则

- 提问：审批规则按什么复杂度定义？
- 提问解释：该问题用于确认审批是单人、双人，还是可以按场景配置。
- 用户决策：可配置审批流。
- 需求影响：不同变更类型、应用、地域或租户可配置不同审批流程。

<a id="d045-rollback-scope"></a>
## D045 回滚粒度

- 提问：菜单版本回滚支持到什么粒度？
- 提问解释：该问题用于确认回滚是整应用、单节点，还是按发布影响范围执行。
- 用户决策：发布范围回滚。
- 需求影响：按一次发布的应用、环境、地域、客户端和目标租户范围回滚。
