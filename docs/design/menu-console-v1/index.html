Experience Strategy

从“菜单不显示”到“安全发布”的完整旅程

主要场景 运营反馈某租户用户看不到新菜单，管理员需要定位原因、修正配置并灰度发布。
Primary user 菜单管理员

负责配置菜单、检查权限和订阅条件、推进审批发布。核心诉求是少切系统、能解释、可回滚。

Secondary user 业务运营 / 客服

发现用户看不到入口时，需要快速确认是配置问题、权限问题、订阅问题还是灰度未覆盖。

Approver 安全审批人

关注高风险变更、默认隐藏策略、发布影响范围和回滚路径，减少误暴露入口。

01 发现问题

从运营反馈或异常告警进入，先选择应用、租户、环境、地域和用户。

需要：上下文筛选、异常入口
02 定位节点

搜索菜单、路由或权限码，在菜单树中定位目标节点并查看当前状态。

需要：菜单树、搜索、状态标记
03 解释可见性

系统逐条说明订阅、权限、地域、客户端和个人规则是否命中。

需要：可见性解释、失败原因
04 调整配置

管理员修改节点、条件或租户规则，并在保存前看到影响范围。

需要：节点配置、影响预估
05 验证发布

通过预览和规则校验后进入审批、灰度、全量发布，必要时回滚。

需要：预览、审批流、发布状态

关键任务流

Web 管理端主路径
选择上下文 定位菜单节点 查看可见性解释 修正条件或权限 运行时预览 提交审批发布

关键反馈

每一步都要回答用户的疑问
  • 我在哪个上下文？应用、租户、环境、地域持续可见。
  • 为什么不可见？按规则逐条解释，不只给布尔结果。
  • 改动影响谁？展示租户、用户和客户端影响范围。
  • 发布安全吗？高风险变更进入审批，支持灰度和回滚。
