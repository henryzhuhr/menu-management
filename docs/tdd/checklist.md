# TDD 参考清单

每次编写 TDD 时，默认参考以下清单，不要求机械地全部写满，但应按这份清单检查是否需要覆盖。

## 清单

- 问题定义与目标
- 总体方案与备选方案对比
- 系统边界与模块职责
- 数据模型、表结构、索引、缓存策略
- 后端接口设计：路由、请求、响应、错误码、鉴权
- 前端页面/组件设计、状态流转、交互约束
- 关键业务流程时序
- 可观测性设计：日志、指标、追踪、审计
- 测试方案：单元测试、集成测试、端到端测试、回归测试
- 发布方案、回滚方案、数据迁移方案

## 使用建议

- 小改动：只写与本次改动直接相关的项
- 中等改动：补齐方案、模块、接口、数据、测试等关键项
- 较大改动：尽量完整覆盖清单中的主要项

## 高风险变更约束

如果本次改动涉及以下内容，TDD 中必须单列说明风险和处理方式：

- 数据库
- 缓存
- 消息
- 权限
- 安全策略

这类改动至少应补清楚：

- 影响范围
- 风险点
- 兼容方式
- 测试方式
- 必要时的回退思路

如果涉及数据库 schema 变更，必须同时考虑：

- 迁移脚本
- 历史数据兼容
- 回滚策略
- 索引与性能影响
