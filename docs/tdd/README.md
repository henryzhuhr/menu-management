# TDD README

本目录维护项目的设计文档。

这里也采用持续更新的方式，不是一需求一份文档。只记录当前开发真正需要的设计结论，不写过重的流程材料。

## 目标

TDD 只需要回答几个最基本的问题：

- 准备怎么做
- 技术栈和工具怎么选
- 涉及哪些模块
- 接口和数据怎么定
- 有没有特别需要注意的约束
- 需要怎么测试

## 建议写法

如果是一个新功能，通常补这几项就够了：

- 方案概述
- 技术选型
- 模块边界
- 接口设计
- 数据设计
- 测试方式

## 维护规则

- 优先更新现有文档，不默认新建新文件
- 设计写到“足够开始开发”即可
- 如果实现改了设计，顺手把文档同步掉
